# 输出整理：原始记录 + 精选入口

## 文件名不是知识库

新产物先遵循已有目录约定。没有约定时，可用 `runs/<UTC时间>_<task-slug>_<短随机ID>/` 表示一次运行；例如 `20260916T104530Z_unfold_7fa2c1` 仅为命名示例。短名便于辨认，ID 防冲突，详细条件进元数据而不是全塞进文件名。创建时检查冲突，冲突就换 ID，不覆盖。

时间只用于唯一性/检索，不代表质量、阶段或因果。文件名中不用 final/final2/latest_ok 等可变判断，运行后不因成功/失败而改名。阶段和用途存在清单里。

原始视频、配置、日志和代码快照/补丁各留稳定位置。重要已验收运行视为记录，不用新运行覆盖；补充验收说明注明日期。无需为每次运行复制整个仓库或资产，优先引用稳定版本/哈希及必要补丁。

## 最小证据与批次

每次值得保留的运行记录：run_id、目标/实验组、创建时间及时区、代码版本与相关修改、命令/工作目录、实际配置、资产/关键环境、输出位置、实际已执行检查。

生成大量候选时用实验组的共享说明/环境/配置 + 每个候选的参数差异、种子和结果，不要求几百篇独立报告。tiny smoke test 可引用现有测试输出；无诊断/复现价值的临时缓存不强制永久保存，清理仍遵守用户确认的保留策略。

`assets/run-manifest.template.json` 是结构示例，不要求已有追踪系统改为这个格式。不适用项可为 null 或删去并说明；“未知”不能填成默认成功。实际生效值可能与配置文件默认值不同，要保存覆盖后结果或足够恢复的覆盖顺序。

## 精选入口按阶段和用途，不仅按时间

为真正有意义的阶段保留代表成果，比如基线、第一次跑通、关键修复后的稳定版本、当前某一明确指标下的推荐版本、典型失败对照。阶段名称来自已确认进展或证据，不能仅按修改时间猜出。

一个成果可有多种用途，不要复制文件来放进多个文件夹。精选项应说明：
- 阶段与可读标题；产物类型（demo/代码/文档/数据等）。
- 实际文件或入口、run_id/对应 manifest（历史来源不明时明确未知）。
- 为什么保留、适合说明什么、已检查到什么范围。
- 关键适用条件；有对照时链接基线，不凭名称宣称全面更好。

“可供汇报”是用途，不是实验成功状态；“当前推荐”必须限定目标/条件和依据。视频只挑一个漂亮案例不能证明稳定性或泛化，批次结论链接批次结果。

选用本包工具时：`artifacts/selected.json` 是精选选择的主要维护位置；脚本生成 `docs/ARTIFACTS.md`，可额外生成便于浏览的 HTML。原始运行事实仍来自 manifest/配置，选择理由在 selected 中；二者职责不同。

脚本只验证清单结构和本地文件存在、生成链接，不会验证物理行为、指标或文字理由，也不会自动挑“最好”。外部 URL 或跨仓库输出应使用现有系统的稳定标识/授权映射；本脚本故意只接受当前 root 内的本地文件。

使用 Understand Anything 原生 Demo 门户时，沿用项目的 `.ua/artifacts.json`（或已有数据目录）登记产物；排序/隐藏偏好独立保存在 `artifact-display.json`，刷新目录或切换任务时不得覆盖用户偏好。隐藏只是从列表移除，原始证据和文件继续保留。不要为采用本包的可选精选脚本而迁移一个已经有效的目录。

## 代码和文档同样要治理

稳定代码入口留在原有 src/scripts/examples；复用逻辑优先参数化或模块化，不每次调参复制一个 demo_new_v3.py。确实不同的算法/变体应明确命名和记录差异，不为减少文件数强行揉成难维护的脚本。

临时脚本在已有 scratch/experimental 区域并记录用途；进入正式工作流时补入口与最小用法。历史成功版本通过 Git revision 和必要补丁追溯，不靠几十份“最终版”脚本。

文档在原主题页更新；只有不同用途/读者、实质独立主题或需要保留汇报快照时新建。不把脚本生成的索引再手写一份。

## 历史与清理

先盘点、关联和索引，后讨论重命名/移动；默认不改原位置。没有来源证据的旧产物可以被列入“待确认”或“视觉参考”，不能伪造它的源码/配置。

归档不等于删除。批量改名/移动/删除需检查脚本、配置、文档引用，准备旧新路径映射并获得相应授权。未获授权不删除用户文件；也不自行设置自动清空几天前输出的任务。

# 项目文档树与维护协议

## 最小入口，按需扩展

先复用现有结构。没有合适入口时，从 `docs/README.md`、`docs/STATUS.md`、`docs/TASKS.md`、`docs/ARTIFACTS.md` 开始；更小的项目可以合并入口与状态。下列是逻辑角色，不要求一开始全部建文件：

```text
docs/
  README.md              项目地图：读什么、当前工作目标、主要维护位置
  STATUS.md              当前阶段、已验证结果、阻塞、近期变化及证据入口
  TASKS.md               下一步、验收条件、依赖与待决策；建议单列
  ARTIFACTS.md            精选阶段产物/代码/文档入口，不列出每个临时文件
  knowledge/             按问题组织的理论与工程说明；有实质内容再拆页
  decisions/             重要方案选择、理由、替代方案、重新考虑条件
  reports/               需要汇报时保存的带日期快照，不是另一份当前状态
runs/ 或已有输出目录      原始运行、有效配置、日志与视频；不要求搬迁旧产物
artifacts/               可选：精选清单、自动盘点/索引及旧路径映射
```

开始工作：读 README 和相关当前状态，定位本次需要的主题/任务/运行记录；不加载所有页面。README 保持可浏览的导航，不复制全部事实。

## 信息放置与更新

| 信息 | 主要维护位置 | 何时改 |
|---|---|---|
| 项目目标、术语边界、已确认前提 | README 或对应背景页 | 目标/范围真正改变 |
| 当前做到哪里、什么已验证、卡在哪里 | STATUS | 有实质进展、回退、阻塞变化 |
| 下一步执行什么、怎样算完成 | TASKS | 接受任务、优先级/依赖变化、关闭任务 |
| 理论、实现机制、接口约定、修改入口 | knowledge 对应主题 | 发现关键机制或实现/条件变化 |
| 为什么选择某方案、为什么放弃某方案 | decisions；小决策并入主题页 | 重要决策或新证据推翻旧决策 |
| 原始配置、命令、检查与输出 | run manifest/实验记录 | 运行创建、结束、补充实际验收 |
| 哪个阶段该看哪个结果/入口 | 精选清单；ARTIFACTS 是视图 | 新代表成果、退化、验证变化 |
| 某次汇报当时说了什么 | reports 快照 | 明确准备汇报时；错误另附勘误 |

“一个主要维护位置”不禁止短摘要：其他页可概括并链接，不重复维护完整条件、指标和实现细节。汇报快照保留当时状态并注明日期/对应版本；当前入口不要把历史快照当实时事实。

## 解释分层，而不是一律少写

主题页顶端先用短段落回答实际问题；下面再放“为什么/如何实现/证据/如何改”。标题优先采用问题，例如“抓取点如何从资产坐标转换到世界坐标？”而不只是“坐标变换”。

理论与工程应互链：理论说明关键变量/假设，工程说明它对应哪个配置、函数或观测。概念需要相对独立讲解时拆成两页并互链，不机械按“理论/工程”重复写两份。

需要更深入时保留必要推导、实例和边界，默认首屏不倾倒这些内容；不要用堆砌术语伪装信息密度。没有相关事实可写就不建“理论大全”等空目录。

重要结论附证据位置与适用 revision/条件；实质复核后记录日期。关联代码改变时检查文档，来不及复核则标记待复核，并指出受影响结论；不对全库机械打过期标签。

## 状态与可执行待办

STATUS 以当前状态为主，保留少量最近的重要变化及链接。不能因写完代码就写任务完成，不能编造百分比；以实际里程碑/检查范围表示进度。

TASKS 的活动项尽量只留当前可执行的少量工作，其他进入 backlog 或“候选探索”。每项写一个明确动作或验证问题、完成依据、关键依赖/阻塞；需要用户判断的选择单独标注，不替用户编造批准或负责人。

示例（任务写法示例，不表示当前项目存在此问题）：
“固定资产与材料，仅改变初始朝向；观察抓取点误差。若误差随朝向系统变化，则优先检查坐标转换。验收：保存配置、对照结果和可定位结论。”

不把每个未知都转成 todo。优先保留会改变方案、解除阻塞或避免高成本重试的问题。已完成项保留结果链接，可按阶段归档，不能只删掉所有完成记录。

## 维护触发与成本

关键事实/决策出现、实验批次结束、接口或默认值改变、阶段成果可展示、任务结束/交接会话时检查受影响资料。细小文件修改不必触发全面盘点；相关文件没变就不要改日期。

生成运行元数据与库存可交给脚本；挑选代表成果、解释因果、决定下一步仍需证据和判断。现有生成视图不得另建手写副本。

文档维护嵌入实际执行会话，不意味着会话关闭后自动运行。需要外部发布时采用已授权目的地和工具；默认不自动上传，尤其不复制私有日志、资产和凭据。

## 后续扩展的准入条件

确实出现重复使用需求时才增加：术语/变量速查、关键决策记录、假设—实验表、典型失败库、可重复的汇报提纲、参数敏感性图表、代码变化影响提示。若可用现有主题页一段话解决，不另建一个子系统。
